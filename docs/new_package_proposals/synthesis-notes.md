## From R2 (ML monitoring)
- `Monitor` ABC: `fit(reference)`, `observe(record)` [abstract], `verdict()` [abstract], `state()`/`restore()`; `_PARAMS` default-deny.
- `Verdict.status ∈ {ok, warn, alarm, insufficient}`; `insufficient` is first-class (below `min_n` never `ok`; last partial chunk never `ok`; outcome verdicts provisional until `label_coverage`).
- Families (subclasses, never `kind` branches): DistributionMonitor (Distance strategy: PSI/KS/JS/chi2/Linf/proportion-z; bins from reference quantiles at fit), StreamMonitor (DDM, PageHinkley/CUSUM, ADWIN, Trigg tracking signal — cheap always-on), OutcomeMonitor (ECE/reliability, Brier+Murphy, BSS + Diebold–Mariano vs DECLARED baseline — reuse pipeline metrics/DM), LabelFreeMonitor (CBPE arithmetic; DLE = pack), OperationalMonitor (decision rate, coverage/abstention, latency pct, error/refusal counts, staleness, action limits), ParityMonitor (replay logged inputs through the SAME node objects; count skewed features/examples).
- Strategy objects: `Reference` (RunReference from run dir; SnapshotReference; LeadingReference; RollingReference — keep a fixed anchor AND a rolling one), `Chunker` (CountChunk/PeriodChunk/SlidingWindow), `Threshold` (constant / reference_std k=3 / alpha (PSI benchmark from n,m,B via NormalDist) / ert), `Response ∈ {log, warn, halt, fallback, rollback}` (halt → exit 3), `Gate` (evidence predicate over MonitorRecords for stage transitions).
- `Profile` value object: mergeable per-field counts/min/max/sum/sumsq/missing/quantile bins/top-k.
- Records: DecisionRecord (per tick; abstain flag+reason; baseline forecast; latency; action-limit hits; stage shadow|paper|live_limited|live; executor ack), OutcomeRecord (joined by decision id, never by time), MonitorRecord (keyed by monitor, slice, window; provisional flag), ProfileRecord, ReleaseRecord (via journal), LabelFreshness.
- Release ladder: shadow → paper → live_limited → live; `gate.require: [{monitor, status, min_windows}]`; promotion refused on any `insufficient`; rollback reverts the MODEL alias; rehearse.
- Tier: stdlib for PSI/KS(asymptotic)/JS/Linf/chi2 stat/z/Wasserstein-1D/ECE/Brier/BSS/tracking/CUSUM/DDM/ADWIN(simplified)/CBPE/quantile-bin isotonic/percentiles/profiles; packs: scipy (exact p), sklearn (calibrators), numpy (MMD), matplotlib, mlflow.
- Pitfalls: p-values at scale (use distances >~1000 rows); fixed PSI thresholds; rolling-only refs; label-free under concept drift; drift≠degradation (page on symptoms); biased outcomes (keep a holdout slice); averages hide tails; coverage collapse looks like low risk; thresholds sourced from the thing they validate.
- Tests: statistic pins (PSI=0 identical, χ² scaling; KS hand case; ECE=0 calibrated; Murphy sums to Brier; DDM 2σ/3σ; PH alarms on shift); insufficient semantics; state round-trip; determinism (byte-identical MonitorRecords); parity golden test; gate refusal; exit 3 on halt; knobs-agree-with-run-dir pin.

## From R3 (API resilience)

- `CircuitBreaker`: states `CLOSED|OPEN|HALF_OPEN|FORCED_OPEN|METRICS_ONLY`; `trip(reason)`/`reset()` ops verbs (kill switch); `permit()`, `record(kind, elapsed_s)`, `on_transition`; business rejections ignored not counted; knobs window{count|time,size=20}, min_calls=5 (NOT 100), failure_rate=0.5, slow_call_s, slow_rate, open_s=30, half_open_calls=1, auto_half_open; ONE BREAKER PER SCOPE (reads/writes/stream); every transition persisted.
- `RateLimiter`: token buckets per scope + bulkhead `max_in_flight` (default 1 for writes); `acquire(scope, cost)`, `release`, `observe(headers)` (Retry-After / RateLimit / X-RateLimit-* — every derived pause capped; venues with no headers run on the configured bucket); backwards clock = zero elapsed.
- `Idempotency` write-ahead ledger (sqlite3): `{key, fingerprint(sha256 canonical intent), created_at, state}` persisted BEFORE first send; states `pending → sent → acked|rejected|ambiguous → acked|rejected|orphaned`; hooks begin/sent/settle/mark_ambiguous/reconcile (executor `find_by_client_id`); key reuse with different fingerprint refused (draft 422). Knobs: key_format uuid4|derived; key_max_len (venue fact); dedupe ∈ {replays, rejects, window, none} + dedupe_window_s; retention_s; on_ambiguous ∈ {reconcile_then_halt, reconcile_then_resend} — resend permitted only when dedupe ∈ {replays, rejects}, refused at config-check otherwise. No PII in keys.
- Loud live switch, corrected: document live capability + `--armed` + env release hash + authenticated unexpired maker-checker arming + executor fingerprint must agree; any mismatch refuses submit without changing the configured rung/executor, while query/reconcile/cancel remain possible. Governor limits are graded document fields.
- Seams: `Transport` ABC `send(method,url,headers,body,timeout)->(status,headers,body)`, timeout {connect_s, read_s} both required; `Signer` ABC `sign(method,path,query,body,timestamp)->headers` (HMAC stdlib; RSA-PSS/Ed25519 pack), skew_window_s + time_probe, refuse to sign when skew exceeds window; `Secrets` + `redact(text)` on every log line/cassette; `Stream` ABC connect/subscribe/next/close, heartbeat_s, stale_after_s, seq_field, on_gap ∈ {resnapshot, reconnect, halt}, queue{max, overflow ∈ {conflate, block, halt}} (never conflate order events); `FakeVenue` tier-1 test double: Toxiproxy fault names, toxicity, seeded rng, virtual clock, JSON cassettes record_mode ∈ {none, once, all} with redaction.
- Injected for tests: clock (mono+wall), sleeper, rng, transport, secrets resolver, ledger path.
- Records: attempt log; breaker transitions; limiter waits; idempotency ledger; arm/disarm events w/ identity hash; correlation ids; redacted request summaries; bodies only under `log_bodies` + redact.

- Core loop = one class with validated injected objects; no mode branches. The full action matrix preserves shadow/paper, and only live-capable cells require exact-intent authority plus a fresh fence.
- Ledger: append-only/single-writer; caller-UUID inbox distinguishes retries from repeats; stale-behind caches rebuild, divergent caches refuse. Process-stop barriers before its final head is journaled. Normal exits journal once; SIGKILL cross-store gaps are reported. HALT remains out-of-band.

## From R4 (observability, alerting, health)
- Alert on SYMPTOMS of the loop: "no successful tick for ≥ 2×period", "act declared but unconfirmed", "exposure over limit", "health went UNHEALTHY". Everything else ticket/log. Page rules: urgent, actionable, requires intelligence, novel; err on removing noisy alerts. Low-traffic loops: count windows ("k of last n ticks"), not rate windows.
- Closed severity vocabulary `info | warning | error | critical` pinned to PagerDuty / OTel SeverityNumber (9/13/17/21) / syslog / Python logging (20/30/40/50) by a test; routing (page/ticket/log) is a separate config dimension; status `firing|resolved`.
- `AlertSink` construction validates config only; reachability is a supervised probe. Core network sinks have real socket deadlines; each custom sink has one daemon worker, disabled without replacement after timeout so one stuck call consumes at most one thread.
- `AlertRouter`: fingerprint dedup, group_wait_s (30), repeat_interval_s (14400), per-severity routes, token-bucket rate limit (critical bypasses rate limit not dedup), inhibition, silences, escalation (escalate_after_s un-acked), ack/resolve; sink calls on a worker thread fed by a BOUNDED queue; put_nowait failure + sink exceptions swallowed and COUNTED; sqlite state so restarts do not re-page.
- `HealthProbe` ABC (name, scope ∈ {local, dependency}, timeout_s, abstract `check() -> ProbeResult`); probes on a background thread; loop alarms if the probe thread dies.
- `Health` state machine `STARTING → READY | DEGRADED | UNHEALTHY → STOPPING`; local failure → UNHEALTHY (stop acting AND stop heartbeating); dependency failure/staleness → DEGRADED (keep observing, refuse acts, alert); failure_threshold 3 / success_threshold 1 hysteresis; TRANSITIONS generate alerts, not levels.
- `Heartbeat` emitters (tier-1): file (mtime + JSON), systemd NOTIFY_SOCKET (WATCHDOG=1/READY=1/STATUS=/STOPPING=1), url (healthchecks-compatible: success, /start, /fail, rid=tick_id); sent only when READY (or DEGRADED-observing as configured); the dead-man's switch is always EXTERNAL.
- `Metrics` registry (tier-1): counter/gauge/histogram; Prometheus naming enforced (base units, `_total`, closed label sets, cardinality cap `labels_max_cardinality` refuses new label values); flushed JSONL per tick; packs prometheus_client / opentelemetry subscribe.
- A durable `tick_start` precedes work; graceful paths append one terminal tick/decision and startup recovery closes unmatched starts after process death. A Python `finally` is not relied on for SIGKILL or host loss.
- `AuditLedger` hash-chained insert-only ledger of declared acts: two-phase `declared → submitted → confirmed|rejected|cancelled → reconciled`; `verify()` walks chain; `anchor` mails/posts the head hash every N rows.
- Arming uses separately authenticated maker/checker proofs, bounded expiry and tighten-only scope bound to an immutable release hash. Halt refuses submits and best-effort cancels; flatten is a separate authenticated reducing act.
- `Readiness` checklist evaluator: JSON checklist (question, required, evidence, waiver) → GO/NO-GO; NO-GO exits 3.
- Config shape `production: {mode, tick{period_s, jitter_s, timeout_s ≤ period, stale_after_s ≥ 2×period, data_stale_after_s}, health{...}, heartbeat{...}, alerts{sinks, routes, group_wait_s, repeat_interval_s, rate_limit, escalate_after_s, inhibit, silences}, logging{dir, level, rotate, queue_size, redact}, audit{path, hash, anchor_every_n, retention_days}, metrics{sinks, histogram_buckets_s, labels_max_cardinality}, slo{objectives, burn_rate_alerts}, act{armed, arm_token_env, kill_switch_file, max_acts_per_tick, max_open_exposure, exposure_unit}, readiness{checklist, waivers}}`. Identity: act.*, mode, tick.*, slo.* graded; alerts/logging/heartbeat/metrics.sinks/audit.path = placement (non-identity like env/outputs/schedule/tracking).
- Records: TickRecord, ActRecord (hash-chained), AlertRecord, HealthTransition, ReconciliationSnapshot, ReadinessResult.
- Tier-1 stdlib: logging(+QueueHandler/QueueListener), json, sqlite3, hashlib/hmac, uuid, smtplib/email, urllib.request, socket, threading/queue, signal, contextvars, http.server (optional /healthz), statistics. Packs: prometheus_client, opentelemetry, sentry (optional).
- Safe default on partial failure = REFUSE TO ACT THIS TICK, keep observing, say why — never fallback (Amazon "avoiding fallback"; SRE "stale beats incorrect").
- Tests: sink/probe timeouts are bounded; heartbeat is independent and stops unhealthy; barriered `tick_start` plus restart recovery closes crashed ticks; ledger ordering/idempotency/anchors verify; live requires exact-intent authorization and fencing; cancel has reserved bounded capacity; identity excludes only exact placement paths; readiness and purity gates hold.
- Pitfalls: paging on causes; heartbeat = "process alive" not "loop healthy"; health checks making soft deps hard + fast automation on dependency probes; no timeouts (HTTPHandler!); rate windows on low traffic; unbounded label cardinality/free-text reasons; silent fallback; alert storms; secrets/payloads in logs (webhook URLs are credentials); multiple log lines w/o shared id; rewritable audit log; duplicated defaults; runbook-less alerts; launching without readiness; arming by config alone; purposeless metrics.

## From R1 (OMS lifecycle and pre-/post-trade risk controls)
- Two facts per report (FIX): `ReportKind` (ACK, REJECT, FILL, CANCEL, REPLACE, EXPIRE, CORRECT, BUST, STATUS, RESTATE) separate from `OrderState`; pending states are waits, not failures; `cum + leaves == qty` invariant; fills dedupe on `exec_id`; DENIED (refused locally) and UNKNOWN (in-doubt) are client-side states no venue sends.
- Order = monotonic state machine + saga: compare-and-set transitions; deterministic client id reused on retry; resolve timeouts against the venue's record, never blind resend; exposure counts WORKING orders; netting vs hedging declared by the executor.
- Reconciliation is a loop with fail-closed start (orders → fills → positions/balances); unknown venue orders tagged EXTERNAL; refuse to start on failure; open-orders endpoints cannot distinguish missing from recently closed; lookback matters.
- Gate taxonomy: size/value, price collars, exposure including working orders, period loss, submit message rate, repeat/duplicate controls, allowlist, calendar, freshness, skew and link state. Cancels bypass business guards and submit budgets but use reserved bounded transport capacity.
- Closed operating states: `TradingState` ACTIVE/REDUCING/HALTED/KILLED; `DataState` LIVE/DEGRADED/STALE/DEAD/CLOSED; `LinkState` CONNECTED/RECOVERING/DISCONNECTED.
- Executor ABC with `spec()` capabilities (dedupes_client_id, supports_replace, has_cancel_on_disconnect, has_dead_man_switch, position_model, precisions); core ships Shadow (default) + Paper (declared fill/slippage/fee assumptions) because sandboxes are low-fidelity or absent (Betfair delayed key trades real money).
- Arming = authenticated maker request plus independent checker approval, bounded expiry and tighten-only scope bound to the immutable release. Live submit needs a fresh permit; the executor's recovery channel constructs unarmed.
- Postmortem lessons: soft blocks alone fail (Citi); alerts nobody reads (Knight's 97 e-mails); periodic exposure and manual throttle bypass (Goldman); collars with stale reference or session gap; never count on cancel/bust (Mizuho); design for the operator's view under pressure — fewer, louder, actionable signals and one obvious safe action; rollback as first response widened Knight's blast radius.
- Venue residue for the child: sides/units/precision, order/persistence types, error mapping, dedup + replace semantics, COD/dead-man availability, rate-limit shape, self-match modes, sandbox existence.

## From R5 (guardrails, kill switches, safe degradation)
- One taxonomy: every limit is *a numeric measure of (proposal, state), over a window, against a bound, at a scope*; only the measure formula, the collar reference, and the calendar keying the window are domain-specific → ONE `Limit(Guard)` parameterised by measure × window × bound × scope; stdlib `Measure` registry + `pkg.module:Measure` doorway.
- `Guard.check(proposal, state) -> Finding`; verdict lattice `allow < warn < amend < refuse < hold < halt`; every guard runs, every finding recorded with value/bound/reason (ESMA per-control trigger stats); composite = max; "no decision" is a proposal (`action: none`), not a verdict; `halt` maps onto exit 3.
- Rung, breaker, and health are orthogonal inputs to a closed action matrix. Promotion uses authenticated distinct maker/checker proofs from `live_limited`, bounded expiry, and immutable release binding; demotion is free. Breaker reset is human-only after cooling-off and never automatic.
- Halt ≠ flatten: halt refuses submissions and best-effort cancels with recorded outcomes. Flattening uses a separately authenticated maker-checker reduction plan; cancels bypass business guards but remain transport-limited through reserved priority capacity.
- Live read/query/cancel channels construct without authority; only `submit(intent, ActPermit)` requires a current ordinary arm or exact reduction authorization, so safety recovery remains available after expiry.
- Default-deny extends to limits: a live-capable document without a per-proposal size limit, correction-aware accounting, and a period loss limit is refused at plan time (FIA: no size limit ⇒ no order); exposure counts working orders.
- Data/model gates are guards too: input age ladder, NaN/range refusal, abstention threshold, realised-error breaker and ramp cap (Zillow).
- Records: one append-only hash-chained serve ledger is authoritative; head-bound breaker/arming/checkpoint JSON files are disposable caches. Exact-intent client references make resumed holds idempotent.
- Worked config block: limits as `{"uses": "limit", "params": {"measure", "bound": {max|min}, "window": {} | {duration} | {count} | {calendar}, "scope": aggregate|per_key|{group}, "include_working", "warn_at", "on_breach": refuse|amend|pause|hold|halt, "pause": {...}, "hold": {ttl}}}`; a `range` guard for NaN/bounds.

## From R6 (decision ledger, attribution, reconciliation)
- One append-only chain per serve series; process starts/stops continue that chain. `tick_start` makes crashes recoverable. Envelopes include caller `payload_digest`, release hash, ledger-assigned sequence/time/previous hash, and final hash.
- A decision carries `legs[]`: `prediction, uncertainty, baseline, expected_value, decision_price, proposed_action, guards[]{name, verdict, reason}, final_action, size` — the DES original/override/output triple so "model wrong" and "guard blocked" are never conflated.
- Ids derive from stable semantic inputs through injected `IdSource`, independent of ledger sequence and wall time. Append looks up caller id and compares caller-only `payload_digest` before assigning envelope fields; record hash then covers the full envelope.
- JSONL uses one O_APPEND write, continuity, torn-tail recovery and graded fsync. `tick_start`, complete decision plans/findings, intents, authority use/authorization and safety-control transitions cross `barrier()`. `flock` is local only; live mandates a graded fenced child lease and stale-token rejection.
- Outcomes are bitemporal and never mutated: `outcome{kind ∈ settled|marked|voided|partial|corrected, effective_at_ms, known_at_ms, weight, terminal, supersedes}`; reports computed as of a `known_at ≤ T` cut (ALFRED vintage semantics); pending is a state, not a negative; derived labels use a strict FORWARD as-of join (`bisect`), features a backward one; settle-to-value and mark-to-market never share a series.
- Attribution closed-form and stdlib: surprise = realised − EV; implementation shortfall split into execution/delay/opportunity/fees pinned to sum; fill rate; markouts at configured horizons; closing-value skill (CLV generalised); Brier + Murphy decomposition on exact stratification, ECE, BSS against the leg's stored `baseline` (same value as ADR-0067's offline skill); cumulative value with max drawdown.
- Backtest-vs-live is a replay, not a re-implementation: verify `inputs_digest`, run the same nodes on stored rows, diff legs; divergence vocabulary `data | nondeterminism | version | guard | state | execution`; pin `net = raw − fees − slippage − carry` across live ledger, replay, offline predictions.
- Venue reconciliation is a periodic job that itself appends: WORM-snapshot the venue's fills/positions/balances/settlements via a Connector, replay the ledger, match on ids then tolerances, classify `timing | missing_in_ledger | missing_at_venue | quantity | price | fee | state | settlement`, gate the next live start (exit 3) on aged `block` breaks.
- Retention/rotation are config knobs with regulatory periods documented as reference points, never coded.

## Merged decisions (final, feeding the proposal)
- The required serve document rung and stable series UUID feed a release binding run, graph, artifacts, code/runtime, source contract, approval and fenced lease.
- Closed policy uses disjoint submit risk effects and covers starting/stopping. LiveExecutor accepts only a canonical ActPermit; raw authority cannot execute.
- Structural planning defers entry construction/fingerprint/data_edge and drops splits. ServingContract supplies explicit entity keys and manifest-bound universe evidence; frozen rows generate their own digests.
- Sequential legs bind input, quote, accounting and risk versions through plan/Intent/permit. The local verify-and-call gate and gateway enforce deadline/fence/idempotency; external races reconcile.
- Serve alone writes the ledger. Caller UUIDs separate retry/repeat; stale caches rebuild. Stop barriers before final-head journaling; hard-kill journal gaps are explicitly reported.
- The UUID root, runtime binding, no-replace rule, bounded cancel lane, deterministic refs, dead-after heartbeat and semantic replay remain foundation contracts.
