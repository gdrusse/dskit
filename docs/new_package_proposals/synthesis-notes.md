## From R2 (ML monitoring)
- `Monitor` ABC: `fit(reference)`, `observe(record)` [abstract], `verdict()` [abstract], `state()`/`restore()`; `_PARAMS` default-deny.
- `Verdict.status ∈ {ok, warn, alarm, insufficient}`; `insufficient` is first-class (below `min_n` never `ok`; last partial chunk never `ok`; outcome verdicts provisional until `label_coverage`).
- Families (subclasses, never `kind` branches): DistributionMonitor (Distance strategy: PSI/KS/JS/chi2/Linf/proportion-z; bins from reference quantiles at fit), StreamMonitor (DDM, PageHinkley/CUSUM, ADWIN, Trigg tracking signal — cheap always-on), OutcomeMonitor (ECE/reliability, Brier+Murphy, BSS + Diebold–Mariano vs DECLARED baseline — reuse pipeline metrics/DM), LabelFreeMonitor (CBPE arithmetic; DLE = pack), OperationalMonitor (decision rate, coverage/abstention, latency pct, error/refusal counts, staleness, action limits), ParityMonitor (replay logged inputs through the SAME node objects; count skewed features/examples).
- Strategy objects: `Reference` (RunReference from run dir; SnapshotReference; LeadingReference; RollingReference — keep a fixed anchor AND a rolling one), `Chunker` (CountChunk/PeriodChunk/SlidingWindow), `Threshold` (constant / reference_std k=3 / alpha (PSI benchmark from n,m,B via NormalDist) / ert), `Response ∈ {log, warn, halt, fallback, rollback}` (halt → exit 3), `Gate` (evidence predicate over MonitorRecords for stage transitions).
- `Profile` value object: mergeable per-field counts/min/max/sum/sumsq/missing/quantile bins/top-k.
- Records: DecisionRecord (per tick; abstain flag+reason; baseline forecast; latency; action-limit hits; stage shadow|paper|live; executor ack), OutcomeRecord (joined by decision id, never by time), MonitorRecord (keyed by monitor, slice, window; provisional flag), ProfileRecord, ReleaseRecord (via journal), LabelFreshness.
- Release ladder: shadow → paper → live; `gate.require: [{monitor, status, min_windows}]`; promotion refused on any `insufficient`; rollback reverts the MODEL alias; rehearse.
- Tier: stdlib for PSI/KS(asymptotic)/JS/Linf/chi2 stat/z/Wasserstein-1D/ECE/Brier/BSS/tracking/CUSUM/DDM/ADWIN(simplified)/CBPE/quantile-bin isotonic/percentiles/profiles; packs: scipy (exact p), sklearn (calibrators), numpy (MMD), matplotlib, mlflow.
- Pitfalls: p-values at scale (use distances >~1000 rows); fixed PSI thresholds; rolling-only refs; label-free under concept drift; drift≠degradation (page on symptoms); biased outcomes (keep a holdout slice); averages hide tails; coverage collapse looks like low risk; thresholds sourced from the thing they validate.
- Tests: statistic pins (PSI=0 identical, χ² scaling; KS hand case; ECE=0 calibrated; Murphy sums to Brier; DDM 2σ/3σ; PH alarms on shift); insufficient semantics; state round-trip; determinism (byte-identical MonitorRecords); parity golden test; gate refusal; exit 3 on halt; knobs-agree-with-run-dir pin.

## From R7 (state/time/lifecycle)
- One loop class, three injected seams: `Clock`, `Feed`, `Executor` (+ calendar). Never branch on mode.
- `Clock` ABC: `now_ms()`, `monotonic()`, `sleep_until(epoch_ms, wake)`; `WallClock` (≤1s sleep slices honour stop flag), `TestClock` (set/advance), `ReplayClock` (feed-advanced). Every decision record carries THREE times: `tick_at` (scheduled boundary/event time), `data_asof` (watermark = max as-of of inputs), `observed_at` (wall). Only `tick_at` orders ticks; monotonic only for pacing/timeouts (PEP 418).
- `Calendar` ABC: `is_open(ms)`, `next_open(after)`, `next_close(after)`; tier-1 `AlwaysOpen`, `WeeklySessions` (config: tz IANA, sessions[{days, open, close}], holidays, special_closes, blackouts, after_open_s, before_close_s; local-time sessions, UTC arithmetic, DST-gap boundary = validation error), `EventWindow`, `Composite`; pack `libs/exchange_calendars.py`; venue-status calendar = child.
- `Cadence` ABC `next_tick(after_ms, calendar)`: `FixedInterval(period_ms, anchor_ms)` drift-free anchor+k·period; `AlignedBar(bar_ms, publish_delay_ms)`; `AtTimes([...], relative=open|close|clock)`; `OnData(poll_ms)`. `Overrun` strategy ∈ {skip, coalesce (default), queue} + max_lag_ms; never concurrent ticks.
- Lifecycle: `INIT → LOCKED → RECONCILING → READY → {WAITING ⇄ TICKING} → STOPPING → STOPPED`, plus `HALTED` (kill switch; refuses restart), `FAULTED` (restartable). Tick phases (hooks on an abstract Tick): 1 gate (calendar) → 2 fetch (`run_acquisition(mode="live")` through connector) → 3 watermark (refuse if tick_at − data_asof > max_staleness_ms; venue skew > max_venue_skew_ms) → 4 decide (same Node objects at asof=tick_at) → 5 record intent (key = sha256(loop_id, tick_at, decision); status=intended) → 6 act (`executor.submit(decision, key)`) → 7 record outcome (acked|rejected|unknown) → 8 checkpoint LAST (atomic).
- Checkpoint fields: loop_id, config_hash, last_tick_at, last_completed_tick_at, pending (intent keys w/o terminal outcome), positions_snapshot_at, halt {reason, at}|null, schema_version.
- `Executor` ABC: `submit(decision, key)` idempotent on key; `query(key)` → acked|filled|rejected|unknown; `cancel(key)`; `snapshot()` positions/open orders/balances; optional `venue_time_ms()`. Rule: submit that raises after the request = `unknown`; never re-submit blind; only `query` moves it; only the executor may say "proved not sent" (NautilusTrader). `PaperExecutor`, `RecordedExecutor` same ABC.
- Startup reconciliation: lock → load checkpoint → refuse if config_hash differs unless `--adopt` → `executor.snapshot()` → resolve pending keys via query → diff ledger vs venue → ALWAYS write a reconciliation record → `on_mismatch ∈ {halt (default, exit 3), adopt, refuse (exit 1)}`; never synthesise venue actions (Nautilus #3176); optional `reconcile_every_s`.
- Single instance: `flock(LOCK_EX|LOCK_NB)` on `<root>/state/<loop_id>.lock`; second copy exits 4; reuse journal's helper.
- Shutdown: SIGTERM/SIGINT set stop flag; WAITING wakes ≤1s; TICKING finishes the phase, never stops between act and record-outcome; checkpoint, release lock, exit 0; `shutdown_grace_s` must be < supervisor grace (refuse otherwise). Exit codes 0 stopped / 3 halted / 1 error / 4 already running. Kill switch persists `halt` in checkpoint AND exits 3 (systemd RestartPreventExitStatus=3); `resume` clears it. Optional NOTIFY_SOCKET.
- Replay: `Feed` (`LiveFeed` vs `ReplayFeed`), `Recorder` writes a per-tick tape (snapshot ids, clock reads, executor responses, RNG seed); replay with `RecordedExecutor` + `ReplayClock` must give byte-identical decision records = the parity test.
- Knobs (identity unless ops): clock.increment (+ new `ms`), serving.cadence.{uses, period_ms|bar_ms ≥1000, publish_delay_ms}, serving.overrun.{policy, max_lag_ms}, serving.max_staleness_ms, serving.max_venue_skew_ms (default 1000), serving.reconcile.on_mismatch, (ops) reconcile.every_s, shutdown_grace_s, lock_path. Give `clock` meaning now (no clocked document ever ran → no hash to orphan); `schedule` stays provenance.
- Tests: TestClock determinism; next_tick across DST; gate refuses holidays/blackouts/buffers; FixedInterval zero drift; overrun policies; crash injection at every phase boundary then restart ⇒ exactly one venue action per key; second instance exits 4; SIGTERM in sleep exits < grace w/ checkpoint; persisted halt refuses restart; two replays of one tape identical; stale ⇒ skipped:stale; skew ⇒ refusal.

## Merged decisions so far (to be revised as reports land)
- Core loop = one class, injected Clock / Feed / Executor / Calendar; phases as hooks; no mode branches; mode ladder (shadow/paper/live) realised by WHICH executor is injected + the arming conjunction.
- Ledger: append-only, record-before-act, checkpoint-last; idempotency ledger persisted before first send; three timestamps; one decision record per tick (journal gets one row per PROCESS, unchanged).

Page rules: urgent, actionable, requires intelligence, novel; err on removing noisy alerts. Low-traffic loops: count windows ("k of last n ticks"), not rate windows.

Identity: act.*, mode, tick.*, slo.* graded; alerts/logging/heartbeat/metrics.sinks/audit.path = placement (non-identity like env/outputs/schedule/tracking).

## From R1 (OMS lifecycle and pre-/post-trade risk controls)
- Two facts per report (FIX): `ReportKind` (ACK, REJECT, FILL, CANCEL, REPLACE, EXPIRE, CORRECT, BUST, STATUS, RESTATE) separate from `OrderState`; pending states are waits, not failures; `cum + leaves == qty` invariant; fills dedupe on `exec_id`; DENIED (refused locally) and UNKNOWN (in-doubt) are client-side states no venue sends.
- Order = monotonic state machine + saga: compare-and-set transitions; deterministic client id reused on retry; resolve timeouts against the venue's record, never blind resend; exposure counts WORKING orders; netting vs hedging declared by the executor.
- Reconciliation is a loop with fail-closed start (orders → fills → positions/balances); unknown venue orders tagged EXTERNAL; refuse to start on failure; open-orders endpoints cannot distinguish missing from recently closed; lookback matters.
- Gate taxonomy (15c3-5, RTS 6 Art 15, FIA 2024, FCA 2018): max order qty/value; price collar per order AND per window, evaluated at send time in every session phase; max position / aggregate exposure (incl. working); daily loss; message rate (NEVER applied to cancels); repeated-execution throttle (latches until human re-enable); duplicate intent; instrument allowlist; calendar; data freshness (LIVE/DEGRADED/STALE/DEAD ladder); clock skew; link state. A missing per-instrument limit is a BLOCK. Overrides only as config entries with `authorised_by` + `expires_at`.
- Closed operating states: `TradingState` ACTIVE/REDUCING/HALTED/KILLED; `DataState` LIVE/DEGRADED/STALE/DEAD/CLOSED; `LinkState` CONNECTED/RECOVERING/DISCONNECTED.
- Executor ABC with `spec()` capabilities (dedupes_client_id, supports_replace, has_cancel_on_disconnect, has_dead_man_switch, position_model, precisions); core ships Shadow (default) + Paper (declared fill/slippage/fee assumptions) because sandboxes are low-fidelity or absent (Betfair delayed key trades real money).
- Arming = three-way agreement (config live + env var + token file from an explicit CLI acknowledgement carrying expiry and the config identity hash); a live executor cannot be constructed otherwise.
- Postmortem lessons: soft blocks alone fail (Citi); alerts nobody reads (Knight's 97 e-mails); periodic exposure and manual throttle bypass (Goldman); collars with stale reference or session gap; never count on cancel/bust (Mizuho); design for the operator's view under pressure — fewer, louder, actionable signals and one obvious safe action; rollback as first response widened Knight's blast radius.
- Venue residue for the child: sides/units/precision, order/persistence types, error mapping, dedup + replace semantics, COD/dead-man availability, rate-limit shape, self-match modes, sandbox existence.

## From R5 (guardrails, kill switches, safe degradation)
- One taxonomy: every limit is *a numeric measure of (proposal, state), over a window, against a bound, at a scope*; only the measure formula, the collar reference, and the calendar keying the window are domain-specific → ONE `Limit(Guard)` parameterised by measure × window × bound × scope; stdlib `Measure` registry + `pkg.module:Measure` doorway.
- `Guard.check(proposal, state) -> Finding`; verdict lattice `allow < warn < amend < refuse < hold < halt`; every guard runs, every finding recorded with value/bound/reason (ESMA per-control trigger stats); composite = max; "no decision" is a proposal (`action: none`), not a verdict; `halt` maps onto exit 3.
- Two orthogonal state machines: mode ladder `shadow → paper → live_limited → live` (promotion human-only, one rung at a time, signed arming record with two distinct principals for ≥ live_limited, mandatory `armed_until`, bound to the config identity hash; demotion free) and breaker `active → reducing → halted` (auto-trips on guard halt, dead feed, lost heartbeat, reconciliation mismatch, repeat/flip anomaly; reset human-only after cooling-off, persisted across restarts, never a timer). Throttles/pauses auto-expire; kills never self-reset.
- Halt ≠ flatten: halt = refuse new proposals + best-effort cancel of working orders (outcome recorded in `none/submitted/failed/partial/unknown`) + optional reduce-only; flattening is risk-taking and only happens when a human enters `reducing`. Cancels are never throttled.
- Money movement is a constructor precondition, not a knob: a live executor refuses to construct without a valid unexpired arming; `paper=True` stays hardcoded in children.
- Default-deny extends to limits: a document armed beyond shadow without a per-proposal size limit and a period loss limit is refused at plan time (FIA: no size limit ⇒ no order); exposure counts working orders.
- Data/model gates are guards too: input age ladder, NaN/range refusal, abstention threshold, realised-error breaker and ramp cap (Zillow).
- Records: append-only `decisions/trips/arming/approvals.jsonl` + reloadable `breaker.json`; submissions idempotent by proposal id so a resumed `hold` cannot double-submit.
- Worked config block: limits as `{"uses": "limit", "params": {"measure", "bound": {max|min}, "window": {} | {duration} | {count} | {calendar}, "scope": aggregate|per_key|{group}, "include_working", "warn_at", "on_breach": refuse|amend|pause|hold|halt, "pause": {...}, "hold": {ttl}}}`; a `range` guard for NaN/bounds.

## From R6 (decision ledger, attribution, reconciliation)
- One append-only ledger per live PROCESS; closed record `kind` family: process, tick, decision (exactly one per tick; a no-op tick emits `final_action: hold`), order, order_event, fill, outcome, recon, snapshot; envelope `kind, id, seq, process_id, recorded_at_ms, schema_version, prev_hash, hash`.
- A decision carries `legs[]`: `prediction, uncertainty, baseline, expected_value, decision_price, proposed_action, guards[]{name, verdict, reason}, final_action, size` — the DES original/override/output triple so "model wrong" and "guard blocked" are never conflated.
- Ids positional (`decision_id = process_id:seq`, `leg_id = decision_id/subject`), digests content-addressed (`inputs_digest`, `run_hash`, `artifact_digests`, `state_digest`) with the existing sha256-canonical idiom; record hash = `sha256(prev_hash + canonical(record − hash))`, genesis 64 zeros, no floats (money/probabilities as decimal strings or ints), no `notes`; anchor `head_seq/head_hash` into the journal production row on stop (a chain alone cannot detect tail truncation).
- Store contract (tier 1, stdlib), two backends behind one ABC: JSONL (serialise-then-single-write on O_APPEND; fsync policy `every` default for live; flock single writer; torn-tail truncation on open; rotation by segment carrying seq/prev_hash; never copytruncate) and SQLite (WAL + synchronous=FULL pinned by test; BEFORE UPDATE/DELETE → RAISE(ABORT); unique id for idempotent append; same id + different content → refuse). Corrections are new records with `supersedes`; readers tolerate unknown fields and upcast.
- Outcomes are bitemporal and never mutated: `outcome{kind ∈ settled|marked|voided|partial|corrected, effective_at_ms, known_at_ms, weight, terminal, supersedes}`; reports computed as of a `known_at ≤ T` cut (ALFRED vintage semantics); pending is a state, not a negative; derived labels use a strict FORWARD as-of join (`bisect`), features a backward one; settle-to-value and mark-to-market never share a series.
- Attribution closed-form and stdlib: surprise = realised − EV; implementation shortfall split into execution/delay/opportunity/fees pinned to sum; fill rate; markouts at configured horizons; closing-value skill (CLV generalised); Brier + Murphy decomposition on exact stratification, ECE, BSS against the leg's stored `baseline` (same value as ADR-0067's offline skill); cumulative value with max drawdown.
- Backtest-vs-live is a replay, not a re-implementation: verify `inputs_digest`, run the same nodes on stored rows, diff legs; divergence vocabulary `data | nondeterminism | version | guard | state | execution`; pin `net = raw − fees − slippage − carry` across live ledger, replay, offline predictions.
- Venue reconciliation is a periodic job that itself appends: WORM-snapshot the venue's fills/positions/balances/settlements via a Connector, replay the ledger, match on ids then tolerances, classify `timing | missing_in_ledger | missing_at_venue | quantity | price | fee | state | settlement`, gate the next live start (exit 3) on aged `block` breaks.
- Retention/rotation are config knobs with regulatory periods documented as reference points, never coded.

## From R8 (venue-neutral execution)
- Intersection across 8 venues: submit a priced buy/sell of one instrument for a quantity; cancel (except sportsbooks); read one order / open orders; read fills; read balances; immediate vs resting lifetime; every venue returns venue-ref + status + filled qty + avg price. ABC: `spec/capabilities/check/submit/cancel/order/open_orders/fills/balances` abstract; `positions` (fill-derived default), `settlements` (empty default), `replace` (concrete cancel→submit; four venues have four semantics), `events` (optional stream) non-abstract.
- Closed status vocabulary of 11: `pending, open, partial, pending_cancel, filled, cancelled, expired, rejected, replaced, unknown, not_sent`; terminality preserved; a venue lacking a state collapses toward LESS certainty (IBKR Inactive → unknown, never rejected); `unknown` first-class; `filled_qty` independent of status.
- Fills are not final: `Fill.status ∈ {pending, final, reversed}`; `PositionBook` undoes reversed fills.
- Idempotency needs a ledger written before I/O; client refs on 7/8 venues with three retry flavours (reject / return original / de-dupe window); Polymarket none; `Ref = (client_ref, venue_ref)` either nullable.
- Keep native units + a declared label; never convert in core (contracts vs shares vs stake; YES-leg vs NO-token; odds invert "better"); money as `Decimal` at the boundary (cents ints, dollar strings, 6-dec ints — never floats). Paper fills work in price space; odds children convert before quoting.
