# Question
Which 15 genuinely distinct advanced architecture families should DS Kit test for normalized terminal-return distributions, pooled and independently per ticker, with model capacity sized to the available history?

# Finding
Current authority and protocol are the ADR-0238 amendments below; the original proposed shortlist/LR grid and pending-decision paragraphs are retained as proposal history, not active blockers.
Proceed with compact time-series encoders and the existing three-component CDF head and weighted CRPS objective. The studies below support testing architectural mechanisms; they do not establish superior stock-return forecasts. No reviewed source establishes a universal industry-standard parameter-to-row ratio. Parameter counts are a budget, not proof of generalization; purged learning curves and blocked validation decide.

## Actual data and implementation audit
393 tickers appeared in the completed unpooled evaluation. Across admitted evaluation cells, training rows range from 42 to 1,302; the median rises from 1,063 to 1,302. Matched pooled totals rise from 330,109 to 421,497. Rows are correlated: median maximum non-overlapping outcome intervals are only 84 in fold 33 and 103 in fold 41. These counts are NOT estimates of effective sample size. Pooling does not make shared market shocks independent.

The current input is a 22-step, ONE-channel return sequence plus 20 base context columns (34 with options). Context is observed at the forecast date, not a multichannel historical sequence. Do not relabel static context as a time axis. iTransformer's cross-variable attention and long-horizon N-HiTS interpolation are therefore poor first matches without new causal data preparation.

Options first appear in this cached panel on January 22, 2024. Folds 33/34 have zero option training observations; fold 35 has median TWO; fold 41 median 183, before task admission. These are dates with at least one observed option value, not complete cases. Base + options needs an availability gate and matched recent-history base control. Training on imputed constants is not an options experiment.

Existing unpooled parameter counts: MLP base 841; GRU 2,777; LSTM 3,081; CNN 4,281. Options counterparts are 1,065, 3,225, 3,529 and 4,729. The old torch_ts object named PatchTST only embeds its last patch: no attention. Do not present it as the published PatchTST. The existing TFT implementation is explicitly TFT-lite, not a full paper reproduction.

## The proposed 15 families
All produce features for the same CDF objective. Paper-specific forecasting/classification heads are replaced; reports must call these compact CDF adaptations, not exact reproductions or pretrained models.

1. Temporal Transformer: positional encoding, self-attention, residual feed-forward blocks; attention control. [Original](https://arxiv.org/abs/1706.03762).
2. PatchTST: actual multi-patch attention using Hugging Face's implementation. [Paper](https://arxiv.org/abs/2211.14730), [official implementation documentation](https://huggingface.co/docs/transformers/model_doc/patchtst).
3. PatchTSMixer: gated patch/channel/feature mixing via Hugging Face. Distinct patch mixer, not a second PatchTST size. [Official documentation](https://huggingface.co/docs/transformers/model_doc/patchtsmixer).
4. Compact Temporal Fusion Transformer: variable-selection gates, LSTM processing and attention; simplified static-context interface disclosed. [Paper](https://arxiv.org/abs/1912.09363).
5. LSTM-FCN hybrid encoder: parallel recurrent and fully convolutional paths, both required to affect the output. This is a classification-to-CDF adaptation, not a forecasting result from the cited paper. [Paper](https://arxiv.org/abs/1709.05206). DA-RNN is excluded because input-attention softmax over our single historical channel is identically one.
6. LSTNet-style hybrid: convolution, recurrent/skip processing and an autoregressive branch, with the short 22-step context limiting periodicity. [Paper](https://arxiv.org/abs/1703.07015).
7. Residual TCN: causal dilated residual blocks, distinct from the existing plain dilated CNN. [Paper](https://arxiv.org/abs/1803.01271).
8. InceptionTime encoder: parallel kernel scales plus bottlenecks/residuals; a classification encoder adapted to distributions, not evidence of forecasting superiority. [Paper](https://arxiv.org/abs/1909.04939).
9. ResNet1D encoder: residual convolutional representation with global pooling; same classification-to-CDF qualification. [Paper](https://arxiv.org/abs/1611.06455).
10. TSMixer: time mixing with separate context fusion; one historical channel makes its channel-mixing component small. [Paper](https://arxiv.org/abs/2303.06053).
11. TiDE-style encoder: residual dense encoding and covariate fusion; terminal-distribution head replaces multi-step decoder. [Paper](https://arxiv.org/abs/2304.08424).
12. N-BEATS-style residual encoder: backcast residual blocks and additive forecast representation; not the original multi-horizon objective. [Paper](https://arxiv.org/abs/1905.10437).
13. TimesNet encoder: learned temporal representation using period-based 2D blocks; short, noisy return histories make this an exploratory hypothesis. [Paper](https://arxiv.org/abs/2210.02186).
14. SegRNN encoder: segment-level recurrent processing; adapt its prediction head to the CDF. [Paper](https://arxiv.org/abs/2308.11200).
15. S4D encoder: diagonal state-space dynamics with residual mixing; tests a different sequence mechanism from attention/recurrent cells. [Paper](https://arxiv.org/abs/2206.11893).

NLP-inspired attention is already represented. There is no timestamped news/text input here, so no claim of an NLP information advantage. Chronos/Chronos-2 and IBM TTM are researched alternatives, not substitutes for fifteen independently trained models: pretrained data provenance, short-context compatibility and terminal-return-distribution alignment need separate checks. Their large frozen parameter count must be distinguished from trainable adapters. No checkpoint downloaded.

## Capacity and training proposal
Actual Hugging Face construction (random weights, no fitting) confirms compact encoders work with a 22-step input. With one layer, width 8, mean patch pooling and a proposed eight-unit head: PatchTST base 1,009 / options 1,121 parameters; PatchTSMixer 1,010 / 1,122. At width 16: 2,793 / 2,905 and 2,138 / 2,250. The encoders' counts and forward shapes are measured; head counts are arithmetic for the proposed head, not completed trained models. Smaller two-unit fusion heads make width-four PatchTSMixer 482 base / 510 options parameters, which fits the proposed 512-parameter ceiling at 128 rows. This establishes two-family feasibility only; all fifteen need exact construction/count tests before training, with no silent replacement or exclusion.

Proposed engineering ceilings, explicitly NOT an industry rule: independent model total trainable parameters <= min(8,192, 4 * fitting rows); pooled total <= min(100,000, floor(pooled fitting rows / 4)). Search encoder widths 4/8/16 locally and 16/32/64 pooled, with fusion-head widths 2/4/8; reduce before fitting, count every head/embedding, and preserve each architecture's defining mechanism. If its smallest faithful adaptation cannot fit, report insufficient history rather than relabeling a different model. Pooled retains the existing shared encoder plus small shared bottleneck and ticker-specific nine-output linear CDF heads. A bottleneck of width eight has 81 trainable parameters per ticker head. Count every head globally and require each local head <=4 times its local fitting rows; retain the existing refusal for unseen ticker heads.

Start base LR grid 0.0001/0.0003/0.001, AdamW, weight decay 0.01, gradient clipping 1, dropout 0.1; unpooled batch min(64, fitting rows), pooled 512. Select on purged pre-2024 development windows, use inner monitoring only for early stopping, and log optimizer steps as well as epochs. Proposed patience 20, ceiling 500, best-state restoration; a ceiling hit remains a flagged incomplete fit until investigated, not automatic success. Initialize and score epoch zero, verify finite gradients and actual parameter movement, and compare half/full-history learning curves before expanding capacity. Seed 11 first; seed 29 sensitivity checks are separate, not best-seed cherry-picking.

Retain all 15 families rather than selecting one architecture per ticker. Each feature set needs 15 pooled models generating forecasts for all eligible tickers and 15 independent models per ticker. For 393 tickers this is 30 global pooled fits and up to 11,790 independent fits per refit; nine windows imply up to 106,380 fits before tuning, repeats and controls. Actual eligibility reduces this number. Overnight completion is unproven; time a representative pilot and project compute before full launch.

For the options arm, fit only on actual options-era rows (at least one observed options input) with >=128 such fitting dates and >=20 monitoring dates; additionally require >=8 disjoint fitting outcome intervals. Keep the global nine evaluation windows, explicitly leaving earlier options cells untrained when ineligible. Freeze its hyperparameters from the base development exercise, avoiding tuning on the 2024–2025 evaluation. Train a base-only control on exactly the same options-era rows; compare both pooled/unpooled on intersecting forecast identities. A train-only constant-column mask zeros unsupported inputs in both training and prediction; scaling uses training observations only. Per-column availability and source dates are recorded. No backfill of 2024 options into earlier years. Measured admission under these proposed gates: zero tickers in folds 33–39, 276 in fold 40 and 300 in fold 41; 93 of the requested 393 never qualify. These 300 are an upper bound before architecture-specific capacity checks. Owner approval of this incomplete historical coverage is required; it does not satisfy an unqualified promise of fifteen trained options models for every ticker.

All 2024–2025 results are now exploratory because we have inspected them. Preserve the untouched 2026 holdout; no holdout use, new data purchase, provider acquisition, cloud spending or live trading is authorized here. Unpooled fits need atomic model/ticker/fold checkpoints, scores, histories, hashes and resume validation. Pooled fits first persist one immutable shared checkpoint plus preprocessing and head map, keyed by architecture, feature set, fold, selected config, seed, admitted universe and data/code/dependency hashes. Every ticker prediction shard must reference that exact checkpoint hash. Resume partial predictions from those weights; never mix shards across refits. Test crash-after-one-shard recovery. Never rerun a successful cell or hold every ticker's scores in RAM.

## Decision needed
Feature wording is pending clarification: assume base-only and base + options only if confirmed or explicitly adopted. The request for every ticker conflicts with data-sized training for some sparse ticker/windows, especially options. Proposed disposition is transparent insufficient-history cells, never fabricated scores or pooled weights labeled unpooled. Repository ADR approval is required before adding the generic encoders/training controls.

## Candidate-review corrections
The first two implementation lenses found four Majors: malformed manifests treated as model skips, orphan pooled scores permitting refit, skip markers bypassing retained-artifact verification, and BiTCN lacking its defining future-covariate branch. The corrected runner checks all persisted ancestors/shards before either fitting or returning a skip, rejects conflicting terminal states, and normalizes manifest failures to integrity errors. New synthetic regressions first reproduced the failures, then passed. BiTCN is now explicitly skipped: 12 eligible architecture families remain; successful synthetic numerical tests alone did not establish architecture identity.
