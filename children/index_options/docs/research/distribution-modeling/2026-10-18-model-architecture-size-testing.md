## Question

For the ADR-0270 (ticker, day) formulation (one data point per (ticker, day); input = price history + that day's chain per listed expiry + DTE; output = one mixture CDF per listed expiry <= 60 DTE; development 2017-2019, validation 2020-2023, holdout 2024-2025 sealed; 118 names), (1) which layer stacks can the existing owners express today and which need a new adapter, (2) how large may the model be for the information the data really holds, (3) how the model-facing features are arranged per branch, (4) which test battery must pass before any screen result is trusted, and (5) what first-screen matrix fits 4 hours on one GPU. Predictability only. The three 2026-10-18 records (feature engineering, market-implied reference and baselines, windows/lead times/cells) are built on, not repeated.

Scope and data touched: read-only; no fit, no optimizer step, no market record dated >= 2024-01-01. Evidence: construction-only parameter counts (modules built on CPU, never trained), the persisted R5 `state.json` curves (fit/monitor bands end 2018-2019; no score file read), and one probe of projected columns (`symbol, date, expiration, bid, ask, underlying_price`) on `/home/russell/data/index_options/theta-strike-screen-20261018/export-frozen/theta`, row groups whose `date` statistics end before 2020-01-01 only (rows < 2017-01-03 dropped), 118-name cohort filter. Every number from that probe is labelled "probe". Probe/counting scripts live in the session scratchpad, not the repository.

## Finding

### 0. Facts that decide the design (file:line, base 1076eeb6)

- **TorchCDF is a fixed recipe.** `TorchCDF` (`dskit/pipeline/libs/predictive_cdf.py:4494`) = encoder + one head `mlp_stack(width + n_context, hidden, act, dropout, 3K x n_tasks)` (`:2758`, `_CDFExternalEncoder` `:3816`, GRU/LSTM `:3761-3767`, CNN `:3769`, MLP `:3672`), softplus scales above `min_scale` 0.1 (`mixture_parts` `:2810`), global `StandardScaler` fitted on the FIT rows only (`:3158`), AdamW (`:3177`), gradient clip 5 (`:3193`), no LR schedule, early stopping on the calibration band with best-weight restore (`_PatienceStop` `:2713`); `patience` set means `epochs` is a ceiling and reaching it raises (`:3205`), so a still-improving fit is lost. `max_parameters` is checked per seed before training (`:3172`). Losses: one global (`nll`, `crps`) plus at least one local (`decision_brier`, `decision_log`, `wing_twcrps`, `tail_crps`) (`_CompositeLossCDF` `:4203`, `_LOSSES` `:4217`); the local terms read a per-row threshold inventory attached by `fit_decision_context` (`:4260`), which the child builds from listed strikes (`DecisionRegionContextBuilder`, `children/index_options/index_options/cdf_study.py:700`; `ChronologicalCDFStudy.decision_context_rows`, `predictive_cdf.py:6070`).
- **The sequence and the context travel on one tensor.** An external adapter receives only `x[:, sequence_indices]` shaped (B, T, C); `context_indices` bypass it and are concatenated to the adapter output before the head (`predictive_cdf.py:3816-3853`). `SequenceEncoderAdapter` (`torch_ts.py:2034`) is the seam; `ArchSequenceEncoder` (`:2052`) exposes the zoo (`dlinear nlinear mlp lstm gru lstm_attn gru_attn tcn cnn1d patchtst transformer tft`, `_ARCHS` `:60`; `mlp` `:332`, `tcn` `:397`, `patchtst` `:446`); `HFSequenceEncoder` (`dskit/pipeline/libs/transformers.py:2235`) is the R5 PatchTST32.
- **CDFExperiment hard-wires two things** (`dskit/pipeline/libs/cdf_experiment.py:320-348`): the head has exactly ONE hidden layer (`hidden=[w]`, w from `capacity.head_widths`), and the pooled regime ALWAYS adds one head per ticker (`head_features=` the ticker one-hot, `:330`). With G=118 and K=3 the per-ticker output block alone is (w+1) x 9 x 118 = 1,062 x (w+1) parameters. R5 used w=2 for this reason (16,289 parameters at 277 groups: 7,479 of them the ticker block).
- **SetMixtureCDF is not screen-grade.** It trains its own NLL-only Gaussian loop and refuses `patience`, `max_parameters`, `training_telemetry`, head routing and any composite loss (`predictive_cdf.py:5116-5148`); it has no sequence branch. Prior evidence for learned set encoders on raw chains: DeepSets -27.0 % and Set Transformer -27.6 % equal-cell CRPS skill vs the horizon empirical at 5 epochs on SPY/QQQ/IWM, while the option proxy + PIT transport was +2.75 % ([memo 2026-09-29](../../memos/2026-09-29-risk-neutral-cdf-architecture-comparison.md)).
- **Architecture was not the lever on price features.** Twelve architectures through the same head, pooled, 92,231 common forecasts: weighted-CRPS change vs the empirical baseline between -0.18 % and +0.17 % ([memo 2026-10-07](../../memos/2026-10-07-advanced-architecture-results.md)); PatchTST32 on 42 price features in 2019 lost to the empirical reference and gained 0.09 % in 2020 ([amendment 6](../../memos/2026-10-15-theta-amendment6.md), "First saved-score inspection"). So the screen should spend its fits on the chain branch, the loss and the size, with the encoder as a secondary axis.
- **R5 curves, read from `state.json`** (`/home/russell/data/index_options/theta-training-20261016/fits/seed11/pooled/*/PatchTST32/{2,3}/pooled/fit/model/state.json`, losses only):

### 1. Architecture: input to layer stack

Input contract: (a) 22 daily returns, (b) about 20 context scalars (DTE terms, momentum, realized-vol ratios, liquidity), (c) chain structure of that expiry: 13 values `logit F_Q(z_k) - logit Phi(z_k)` plus about 10 scalars, optionally a variable contract set, (d) ticker identity. Output: Gaussian or Student mixture over z. Parameter counts below come from `TorchCDF(...).parameter_count()` (`predictive_cdf.py:3229`) with 22 sequence steps x 1 channel and 43 context columns (20 + 23), K=3, tanh, constructed on CPU and never fitted. "Shared" = no ticker routing (`head_features` absent, expressible in `TorchCDF` directly, NOT in `CDFExperiment`); "tickers" = 118 per-ticker heads as `CDFExperiment` forces.

| ArchSequenceEncoder `mlp` hidden 32 -> 16 | 1,264 | 1,411 / 4,570 | 1,825 / 11,302 | 2,377 / 20,278 |
| `gru` hidden 16, 1 layer -> 16 | 1,184 | 1,331 / 4,490 | 1,745 / 11,222 | 2,297 / 20,198 |
| `gru` hidden 8 -> 8 | 336 | 467 / 3,626 | 833 / 10,310 | 1,321 / 19,222 |
| `tcn` hidden 16, k 2, dil [1,2,4,8,16] -> 16 | 2,432 | 2,579 / 5,738 | 2,993 / 12,470 | 3,545 / 21,446 |

K=1 removes 54 parameters from a shared w=8 head (3 outputs instead of 9) and 6,372 from the ticker block; Student vs Gaussian changes nothing (fixed degrees, `_StudentFamily` `:3962`). The set encoder (`SetMixtureCDF`, 24 nodes x 5 fields + 24 masks + 43 context) is 1,481 (deepsets [16,16]), 2,617 ([32,16]) or 3,705 (attention [16,16]) parameters but cannot be early-stopped or given the composite loss (section 0).

**Recommended stacks for the first screen** (all pooled, 3-component Gaussian mixture, `crps` + `tail_crps`, lr 3e-4, AdamW, batch 512; loss/size axes in section 5):

- **S1 "flat anchor MLP"** (about 1.8k parameters, shared head): 22 returns -> Linear(22,32)+ReLU [736] -> Linear(32,16) [528] -> concat 43 context (13 chain logits + 10 chain scalars + 20 price/DTE scalars) -> 59 -> Linear(59,8)+tanh+Dropout(0.1) [480] -> Linear(8,9) [81] = **1,825** (ArchSequenceEncoder `mlp`, `CDFExperiment`-compatible; 11,302 with ticker heads). Why: cheapest honest "market CDF as feature" model; the 22-return branch is a linear-ish summary, which is all the 12-architecture evidence supports.
- **S2 "GRU + context"** (about 1.7k, shared head): 22 steps x 1 channel -> GRU(1->16) [912] -> Linear(16,16) [272] -> concat 43 -> 59 -> Linear(59,8)+tanh+Dropout(0.1) [480] -> Linear(8,9) [81] = **1,745** (11,222 with ticker heads). Why: the temporal challenger recorded on 2026-09-28 ([temporal screen](2026-09-28-temporal-mlp-gru-screen.md): GRU won 257/357 folds but only 57/126 from 2019 on).
- **S3 "PatchTST32 incumbent control"** (about 9.4k shared / 18.9k with tickers): HF PatchTST d_model 32, 1 layer, patch 4 stride 3 -> 32 (8,704) -> concat 43 -> 75 -> Linear(75,8) [608] -> Linear(8,9) [81] = **9,393**. Why: bridges to R5/R6 and to the 12-architecture table; it is intentionally above the effective-sample ceiling of section 2, so a tie with S1/S2 is the expected, informative result.
- TCN16 (2,993) and DLinear (1,297) are the cheap fourth/fifth encoders (section 5).

**Existing-owner limits and what needs a new adapter** (each is an ADR item, none is written here):

1. **Two-branch encoder (chain set AND return sequence).** The external seam gives an adapter ONE (B, T, C) tensor; the contract tensor (nodes x 5 + mask) cannot ride beside the return sequence. Two ways: a `SequenceEncoderAdapter` subclass that consumes a padded token tensor (22 return tokens + N contract tokens, type flag + value channels) and applies a per-type embedding, or a new `_ENCODERS` kind with `set_indices`. Not recommended for the first screen: the pricing identity already gives the chain as a 13-vector (feature record, section 2) and a set encoder spends parameters learning it (section 0, -27 %).
2. **Shared head without ticker routing in `CDFExperiment`** (`cdf_experiment.py:330`): a capacity key such as `pooled.identity: "head" | "none"`; and a deeper head (`hidden` list) instead of `[w]`. Needed to run S1/S2 at 1.7-1.8k rather than 11k.
3. **DTE-bucket routing.** `head_features` already routes by any one-hot; a 4-bucket DTE one-hot (7-14, 15-28, 29-45, 46-60) as the task would give four 9-output heads (4 x (w+1) x 9 = 324 at w=8) in place of the 118 ticker heads. Expressible in `TorchCDF`; not in `CDFExperiment` (same gap as 2).
4. **Market-anchored (residual) head.** No owner feeds a base CDF to the mixture head. `OptionImpliedTransportCDF` (`:1814`) fits a static 21-knot PIT map, `DynamicPITRecalibratedCDF` (`:1997`) a rolling one, `BetaTransformedCurve` (`:1211`) / `BetaTransformedPoolCDF` (`:2114`) a beta map on a base curve, none conditioned on features by a network. Section 3 specifies the cheapest form (probit-PIT target transform) and what it needs: a curve-composition wrapper and a panel column; it fits the existing `decision_brier` loss unchanged.
5. **Per-ticker embedding** (entity embeddings, [Guo & Berkhahn 2016](https://arxiv.org/abs/1604.06737)) instead of a one-hot head: a small adapter; defer. With 118 names and about 36 independent name-months each, a per-ticker head of 9 x (w+1) parameters is itself over-parameterized (section 2).

Student vs Gaussian: heavy tails are what the standardized z carries (short horizons, earnings), so Student components (integer df >= 3, fixed) are a cheap axis (zero parameters); the 2026-09-28 HPO found no Student winner on index ETFs ([memo](../../memos/2026-09-28-predictive-cdf-hpo.md)), so it is a challenger, not the default. 1 vs 3 components: K=3 is the incumbent (R5/R6); K=1 is the null-hypothesis shape for a model that sees the implied CDF.

### 2. Size versus data

**How much independent information.** Rows are about 318k (E=4, range 170-500k) but dependent three ways: labels of one (ticker, day) share a price path across its 2-6 expiries; consecutive origins overlap (a 31-day label spans about 21 origins); names share a market factor (probe rho about 0.25, so about 4 independent names per period). Independent-ish counts:

- idiosyncratic, one horizon: 118 names x 34 months (36 less monitor and purge) = **4,000 name-months**; if short expiries add non-overlapping windows (weekly horizons, 756/5 per name) the ceiling is 118 x 151 = **17,800**; design effect rows/N_ind about 18-80.
- market-state information: 34-36 months, a few dozen distinct volatility regimes. Anything the model must learn about "how wide is the market's CDF relative to the physical one in regime X" rests on this number, not on 318k.

**Budget rules.**

- Repo cap (ADR-0236/0270 capacity rule): `max_parameters = min(absolute 100,000, 0.25 x fit rows)` (`cdf_experiment.py:326`; 2018 R4: 61,266 x 0.25 = 15,316 refused 16,073-16,091-parameter arms before any fit, memo "Capacity refusals"). At 318k rows the cap is 79.5k: non-binding for every stack here, so the cap does not protect against overfitting at this sample; it only bounds compute. Keep it as the hard ceiling.
- Effective-row version of the same rule: 0.25 x N_ind = **1.0k (4,000) to 4.5k (17,800)** free parameters. S1 and S2 (1.7-1.8k) sit inside; S3 (9.4k) and any ticker-routed variant (11k+) sit 2-9x above. The ticker block is the sharpest case: 118 heads of 9 x (w+1) parameters, each fed by about 34 independent name-months.
- Prediction-model sample-size criterion ([Riley et al. 2020, BMJ 368:m441](https://dspace.library.uu.nl/handle/1874/457642); the shrinkage criterion, S >= 0.9, is from the paper and its companion `pmsampsize`, formula quoted from memory): n = P / ((S-1) ln(1 - R2_CS/S)). With an expected Cox-Snell R2 of 0.02-0.05 (the order of the +2.75 % CRPS skill of the transported market proxy) this is 445 x P to 175 x P independent observations per estimated parameter, i.e. P <= 9-23 at N_ind 4,000 and 40-100 at 17,800. It is a linear-model bound: a regularized, early-stopped network has fewer effective degrees of freedom than parameters, but it says the learnable "signal" is tens of dimensions (scale ratio, skew, tail weight, event kink), which is why anchoring on the market CDF (section 3) is the data-efficient design, not a bigger encoder.
- Weights matter more than counts ([Bartlett 1998](https://doi.org/10.1109/18.661502), from memory, not re-fetched). AdamW's decay is decoupled ([Loshchilov & Hutter 2019](https://arxiv.org/abs/1711.05101)): shrink per step is lr x wd. At the inherited lr 3e-4 and wd 0.01 over 20,000 steps the weights shrink by exp(-3e-6 x 20,000) = 0.94: the inherited weight decay is almost no regularization. Screen wd 0.3 (9e-5 per step: exp(-1.8) = 0.17 after 20,000 steps). Dropout 0.1 after an 8-wide layer is negligible; 0.1 is kept for the 16-wide and larger stacks.
- Memorization is cheap: networks fit random labels ([Zhang et al. 2017](https://arxiv.org/abs/1611.03530)), so train loss falling says nothing; the label-shuffle control (section 4) measures how fast THIS stack memorizes.

**Recipe.** Budget tiers declared before outcomes: **tier 1 about 1-2k** (S1, S2, DLinear, K=1 variants), **tier 2 about 3-4k** (TCN16, widths 16), **tier 3 about 9-12k** (PatchTST control; ticker-routed variants only where `CDFExperiment` forces them). Batch 512 (inherited; 620 steps/epoch at 318k rows), lr 3e-4, K=3, patience 10, ceiling 120, seed 11. Two duplicate recipes at seed 29 give the seed noise floor; promotion keeps seeds 11/29/47 as separate cells (ADR-0270 section 4). Do not average seeds into one mixture inside a screen cell (`seeds=[11,29]` doubles components and cost and hides the seed spread).

**Early stopping.** The inherited monitor band (40 origins, about 14-19k rows at E=4) is one regime and 118 x 2 = 236 name-months: R5 fold 2 stopped at epoch 1 because Sep-Nov 2018 was a volatility shock that every epoch of 1997-2018 learning made worse. Two defensible choices, declared in the fold table (`cal_n`, no code): keep 40 (ADR-inherited) or widen to **126 origins** (about 6 months, about 59k rows, 700 name-months) at the price of 17 % of the fit window. Recommendation: 126 for the screen, because a 2-month monitor cannot rank epochs across regimes; patience 10 is then 10 x 620 = 6,200 steps, double R5 fold 3's patience in steps. Early stopping itself is the right shrinkage here ([Prechelt 1998](https://doi.org/10.1007/3-540-49430-8_3), from memory), but the stopping band must be wider than one regime.

**Reading the persisted curves** (`state.json`: `losses` = per-epoch mean TRAIN composite measured in train mode with dropout on and weights moving; `monitor_losses` = eval-mode band loss, only when `patience` is set; `best_epochs` is 1-indexed; `diagnostics.epoch_zero_monitor_loss`, `parameter_delta_l2`, `optimizer_steps`). Compare changes, not levels (train and monitor are different periods). With M0 = epoch-zero monitor, M* the best, e* the best epoch, T train:

- **No learning** (R5 fold 2): e* <= 2, or (M0 - M*)/M0 < 0.1 % (R5: -0.14 %), while T falls by >= 2 % (R5: -8 %), and the monitor rises monotonically after e*. The trained network never beat the untrained one on the band.
- **Learning** (R5 fold 3): e* >= 5 and (M0 - M*)/M0 >= 0.5 % (R5: 5.6 % over 49 epochs), monitor flat or rising by < 0.2 % over the patience window, train still falling slowly.
- **Overfit**: U-shaped monitor, e* in [3, ceiling/2], and (M_end - M*) larger than the paired-block standard error of the band, with the train/monitor difference-in-differences ((M_e - M0) - (T_e - T0)) growing monotonically.
- **Under-fit**: e* within 20 % of the ceiling, a recorded "ceiling" skip (`:3205`), train still falling > 0.1 %/epoch at stop; confirm by doubling width: train and monitor both improve.
- **Drift versus overfit** (R5 fold 2 cannot be told apart from its curve alone): add an in-regime holdout. A shared-head model (no ticker routing) can score 15 % of the names held out of FIT but inside the same dates; if the held-out names improve while the time band degrades, the cause is non-stationarity, and shrinking the model will not help (normalize by scale, anchor on the market, widen the band). With per-ticker heads this check is impossible ("unseen head in the calibration rows", `:3105`), another reason to drop them.
- Skill is not visible in these curves: the band loss must also be reported for the references (horizon empirical, pooled standardized empirical, market) on the same rows, so that "monitor improved 5.6 %" can be read as skill or not.

### 3. Feature engineering for the model

**Branches** (columns of the panel; `sequence_indices` oldest to newest, `context_indices` = the rest):

- **Sequence branch (22 x C).** C=1: `asinh(ret_lag_k / rv_22)`, the daily return in the name's own volatility units (the panel's `ret_lag_k` are raw returns, standardized by one global scaler `:3158`, so a high-vol name's quiet day and a low-vol name's shock land on different scaled values). Optional C=2: add `log(|ret_lag_k|/rv_22 + 0.05)`. Same-time bounded transforms only (`asinh`, log ratios): fold-aware winsorization cannot live in the panel, and the scaler is fit-window-only by construction. Stop at 22 steps: the build refuses a TCN whose receptive field is below the window (`torch_ts.py:2106-2113`).
- **Context (b), about 20.** DTE: `log_sessions_to_expiry`, `calendar_days_per_session`; return state: `momentum_5/22 / (rv_22 sqrt(sessions))`, `log(rv_1/rv_22)`, `log(rv_5/rv_22)`, `log(rv_66/rv_22)`, `down_rv_22/rv_22`, `up_rv_22/rv_22`, `log rv_22` (annualized level); liquidity: `vl_log_volume_ratio`, `vl_log_dollar_volume`, `log vl_amihud`; two cross-sectional same-day scalars (median `log(rv_5/rv_22)` over the cohort; fraction of names with a down 5-day move) as the market-state proxy that a pooled model otherwise lacks. Ratios to `rv_22` mean no fold-aware statistics are needed.
- **Chain branch (c), about 23.** 13 values `d_k = logit(F_Q(z_k)) - logit(Phi(z_k))` (below) with `F_Q` clipped to [1e-4, 1 - 1e-4] and `d_k` bounded to [-4, 4]; plus `log(iv_h/(rv_22 sqrt 252))`, `rr25/iv_h`, `bf25/iv_h`, term slope to the next listed expiry, `event_kink_h`, `log half_spread_over_premium`, `log n_usable_strikes`, zero-bid share, `z_min_listed`, `z_max_listed` (the range over which `F_Q` is the market and not the tail completion), and a chain-valid flag. Neighbouring-expiry scalars (IV ratio to the previous/next listed expiry, DTE gap) carry "that day's whole chain" at fixed width without a set encoder; a missing neighbour is 0 plus its flag. Missing chain features use the fit-only median plus an explicit missing flag; `CDFExperiment` imputes by median (`_arrays`, `cdf_experiment.py:350`) but does not add flags, so the flags are panel columns.
- **Ticker identity (d).** Not as 118 routed heads in the first screen (section 2). Its information is carried by `log rv_22`, `vl_log_dollar_volume`, the strike-spacing-in-sigma scalar and the chain scalars; the explicit alternative is a coarse declared group (liquidity tercile x weekly-listed flag, 6 columns).

**Standardization.** One global `StandardScaler` per input column on FIT rows only (`:3158`, `_scaled_features` `:3236`, `mask_constant_features` zeroes constant columns), so sequence lags are standardized per lag across the pooled fit window, chain logits per threshold. This is adequate because every scale-sensitive quantity has already been divided by the row's own scale. Pooling means rare regimes (2008-style) are absent from 2017-2019 fits: a 2020 validation row can sit outside the training support of `iv_h_over_rv`, `log rv_22` and the chain logits (feature record, "Regime dependence"); report skill also with 2020-02-15..2020-06-30 removed (declared sub-period, not a selection).

**How DTE enters.** The target is already `terminal_return / (rv_22 sqrt(sessions))`, so the sqrt-time scaling is built in; what remains horizon-dependent is vol mean reversion, kurtosis decay (CLT) and event inclusion. Enter `log_sessions` (smooth over 5-42 sessions; the 7-60 calendar-day range is about 1.6-3.7 in log) plus `calendar_days_per_session`; raw DTE and sqrt(sessions) are near-collinear with these and add nothing. The implied CDF vector already lives at the row's own z grid, so it needs no DTE interaction to be comparable across expiries; the head learns "how much to trust or correct it at this horizon" through the first hidden layer. Give it the interaction explicitly (3 columns: `log_sessions x {mean d_k, d_{-1.5}-d_{+1.5}, d_0}`) when the head is narrower than 8 units. A DTE-bucket routed head (section 1, item 3) is the alternative: an extra axis, not the default.

**The implied CDF as logits minus the Gaussian baseline.** Yes. (i) Probabilities near 0 and 1 carry the tail information the Brier and tail terms score; in raw probability a move from 0.010 to 0.020 is a difference of 0.01, in logit it is 0.70. (ii) Subtracting `logit Phi(k)` centres the vector at "the market agrees with a Gaussian of the entry-known scale": all zeros is a meaningful point, so the first layer starts near a sensible prior and the standardization removes the large common component. (iii) The tail entries (|k| >= 2.5) are tail completion, not quotes, when strikes do not reach (probe: strike spacing 0.16-2.05 sigma on six names, feature record section 0), hence the `z_min/z_max` scalars; do not let the network read `d_{+-3}` as market information on thin chains. (iv) Do not feed raw quantiles `rn_q_*`/`rn_iqr` as the main representation: they are in z units, which is fine for scale but loses the threshold layout of the loss; keep two or three as scalars.

**Residual versus free target** (strike-region objective).

| | free target: mixture on z, `d_k` as inputs (exists today) | residual: model corrects the market CDF (new adapter) |
|---|---|---|
| mechanism | the net must reproduce the market's shape (skew, event bimodality, smile curvature) from 13 numbers through an 8-16 unit layer and a 3-Gaussian mixture | `F(z) = G(F_Q(z); theta(x))` with `G` monotone, e.g. one `probit` mixture: target `w = Phi^-1(F_Q(z_obs))`, thresholds `w_k = Phi^-1(F_Q(z_k))`, mixture on `w`, init near N(0,1) = the market |
| strike-region fit | resolution at listed strikes is whatever the mixture can express; shape error shows up exactly as Brier at the strikes | exact at the market's strikes by construction when theta = identity; the correction is a smooth probability-space transport |
| data efficiency | highest variance: N_ind about 4-18k learns a shape map | theta has 2-6 degrees of freedom (shift, log-scale, tail weights) conditional on state: the 21-knot PIT transport reached +2.75 % with no network |
| failure modes | at 5 epochs on ETFs: -27 % (set encoders), -0.6 % (rich MLP) | cannot create mass the market lacks (bimodality absent from `F_Q`, tails that are tail completion); noise in `F_Q` at the wings enters the target; rows without a valid chain need a fallback expert |
| owners | `TorchCDF` today | `decision_brier` loss runs unchanged on `w`-space thresholds (the event `z <= z_k` equals `w <= w_k`), but scoring and the study compare in z: needs a composition `_Curve` (like `BetaTransformedCurve` `:1211`) and a panel column pair (`w_obs`, `w_k`); about one adapter and one curve class |

Prior evidence ([memo 2026-09-29](../../memos/2026-09-29-risk-neutral-cdf-architecture-comparison.md), [Shackleton, Taylor & Yu 2010](https://doi.org/10.1016/j.jbankfin.2010.04.006), [Fackler & King 1990](https://doi.org/10.2307/1242339)) favours the residual form for the strike-region objective: it concentrates capacity on the one thing the chain cannot give (the Q-to-P wedge) and protects the strike grid, where the market is most precise. Recommendation: the first screen runs the free-target stacks (all expressible today) with the chain-off arms as the control; the residual adapter is item R1 of the ADR packet and its arm runs in the same matrix if approved. Bound the Brier-space residual, never NLL on `w` (a clipped PIT near 0 or 1 dominates a likelihood). Calibration of the learned correction is a recalibration problem ([Guo et al. 2017](https://arxiv.org/abs/1706.04599) temperature scaling is its one-parameter case).
